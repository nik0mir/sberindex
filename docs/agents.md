# Как пользоваться агентами munnet

Одна страница: кого звать на каком этапе, что вы получите и как это быстро прочитать. Подробности каждого агента —
в `.claude/agents/`, общие правила, факты о данных и шкала жюри — в скиле `munnet-agents`.

## Коротко

- **18 агентов, три роли.** Делают работу и правят файлы — семь `expert-*`. Ищут ошибки — четыре проверщика:
  `check-facts` (данные и числа), `check-repro` (прогон с нуля), `check-ux` (понятность), `devils-advocate`
  (попытка опровергнуть вывод). Ставят оценку по шкале жюри — шесть судей `judge-c1…c6`, по одному на критерий,
  и председатель `judge-council` (сводный балл и план). Проверщики и судьи файлы не правят.
- **Одно правило:** после работы эксперта — проверщик, в конце этапа — судья его критерия, 04.10 и 06–07.10 — совет.
- **Помнить достаточно четыре имени:** `expert-data` (сейчас), `judge-c5-interpretation` (выбор сюжета),
  `check-ux` (перед тем как показать текст людям), `judge-council` (самопроверка).
- **Ничего на слово:** каждый агент подтверждает утверждения командой и её выводом. Что не проверено, помечено
  «не проверено».

## Сейчас: этап 1 по шагам

1. «Используй expert-data: доведи этап 1 — `python -m munnet panel eda` с нуля без ошибок, жёсткие контрольные
   числа `outputs/panel/controls.json` сошлись, отчёт `docs/eda.md` собран; признаки узлов — только на этапе 2».
2. «Используй check-facts в режиме „данные“» — проверит инварианты и проследит 10 случайных МО от сырых файлов.
3. «Используй expert-economist: выбери сюжет по `docs/eda.md`» — вернёт матрицу кандидатов с учётом T14
   и критериев отказа и рекомендацию.
4. «Используй judge-c5-interpretation, режим „потенциал сюжета“» — прогноз уровня по каждому сюжету и премортем.
5. Решение принимаете вы; оно записывается в `PLAN.md`.

Что помнить о данных при выборе: `value` — оценка средних безналичных трат **жителей** МО, а не трат в МО.
Траты приезжих не видны, поэтому «курортный» тип по тратам не выделить; траты жителей вне своего МО (поездки,
онлайн) по описанию набора входят, но модель привязки не раскрыта (скил `munnet-agents`, раздел 5, п. 15).

До начала этапа 2 — **калибровка судей**: шесть судей в режиме «финал» на почти пустом репозитории, затем
`judge-council` в режиме «калибровка». Ожидается 0 почти везде; судья, который ставит заглушкам 1 и выше,
слишком мягок — председатель назовёт пункт его промпта, который надо ужесточить.

## Кто есть кто

| Агент | Отвечает на вопрос | Что вернёт |
|---|---|---|
| `expert-data` | Правильно ли собраны данные и что в них видно? | код этапов `panel`, `eda`, `features` с тестами, «Факты разведки», покрытие, выбросы |
| `expert-economist` | Какой вопрос решает типология и что значат типы? | матрица сюжетов с рекомендацией; профили, названия и правила типов, польза |
| `expert-network` | Какие правила рёбер и почему выбрано это? | `network.py`, таблица «правило × измерение», выбор с чувствительностью |
| `expert-clustering` | Какие методы, сколько кластеров, как меняются типы? | методы трёх семейств, синтетика, выбор, динамика |
| `expert-icvi` | Как посчитаны шесть индексов и что они говорят? | `icvi.py` с тестами, таблица «метод × метрика», разбор согласия |
| `expert-viz` | Как показать, чтобы поняли и захотели исследовать? | графики для жюри, лендинг, PDF, скриншоты 1440 и 375 px |
| `expert-writer` | Как рассказать коротко и проверяемо? | раздел отчёта, README, заявка, реестр чисел |
| `check-facts` | Верны ли данные и каждое число? | таблица расхождений |
| `check-repro` | Повторит ли посторонний расчёт с нуля? | таблица R1–R15 |
| `check-ux` | Поймёт ли читатель за 30 секунд? | тест 30 секунд, правки «было → стало» |
| `devils-advocate` | Можно ли опровергнуть главный вывод? | «устояло / ранено / опровергнуто» |
| `judge-c1-methodology` … `judge-c6-viz` | Какой уровень по строке шкалы? | уровень 0–3, доказательства, исправления |
| `judge-council` | Сколько набираем и что делать первым? | балл из 3,00, пять пунктов «Сделать сейчас» |

## Как звать

- Обычной фразой с задачей и границами: «Используй expert-network: сравни правила рёбер по окнам 2023 и 2024».
  Точно конкретного агента: `@"judge-c2-network (agent)" режим «этап 2»`.
- Судьям и совету — всегда режим («этап N», «финал», «потенциал сюжета», «калибровка») и что изменилось.
  **Свою оценку, ожидания и оценки других судей не передавайте** — это якорит судью.
- Совет: запустите нужных судей параллельно сами, каждого в свежем контексте, затем `judge-council` в режиме
  «сводка» с их отчётами. Сам председатель запускает судей, только если в вашей версии Claude Code работает
  вложенный запуск; иначе он вернёт готовые задания.
- Судьи и проверщики вызываются только явно: они долгие и дорогие (один судья — 5–15 минут, полный совет —
  десятки минут). Автоматически может сработать лишь `check-facts` после изменений в данных.

## Как читать ответ

**Эксперт** — пять блоков: «Итог» (что сделано, главный результат с числом) → «Проверено» (команды и результаты) →
«Решить участнику» (развилки с рекомендацией — ваше решение нужно здесь) → «Изменённые файлы» → «Дальше»
(кто проверит).

**Судья** — первая строка вида
`Критерий 2 · уровень 1 из 3 («удовлетворительно») · вклад 0,15 из 0,45 · уверенность средняя · режим этап 2`,
под ней — «Почему не выше» и «Главное исправление». «Не начато» в промежуточном режиме — не провал, а работа
по плану; рядом дан прогноз уровня. Таблица исправлений отсортирована по приросту балла на час: берите сверху.

**Совет** — первая страница: взвешенный балл из 3,00 с диапазоном, таблица шести критериев, пять пунктов
«Сделать сейчас» с исполнителем и проверяющим, блокеры. Внизу — строка для журнала и сырые отчёты судей.

**Проверщики** — серьёзность: «блокер» ломает вывод или воспроизводимость, «важно» заметит жюри, «мелочь» —
шлифовка. **Адвокат дьявола:** «ранено» — впишите оговорку в текст; «опровергнуто» — меняйте вывод,
а не формулировку.

**Сколько стоит шаг уровня** (баллы по п. 6.3 Положения: плохо — 0, удовлетворительно — 1, хорошо — 2,
отлично — 3; максимум 3,00):

| Критерий | Вес = шаг уровня | Максимум |
|---|---|---|
| 1. Методология | 0,15 | 0,45 |
| 2. Сеть и признаки | 0,15 | 0,45 |
| 3. Сравнение методов | 0,15 | 0,45 |
| 4. ICVI | 0,15 | 0,45 |
| 5. Интерпретация | 0,30 | 0,90 |
| 6. Визуализация | 0,10 | 0,30 |

Любая подтверждённая методологическая ошибка даёт критерию 1 «плохо», а при равенстве баллов решает критерий 5.

## Если что-то пошло не так

- **Хук заблокировал нужную команду.** Агент получит причину и напишет, что хотел проверить. Проверяющие пишут
  только во временную папку и запускают этапы только с временным конфигом (скил, раздел 8). Ложное срабатывание —
  поправьте `.claude/hooks/readonly_guard.py` и добавьте случай в `.claude/hooks/test_guard.py`.
- **Нет браузерной панели** (облачная сессия). `judge-c6-viz` и `check-ux` делают статический аудит и пишут
  «в браузере не проверено». Playwright — только с вашего согласия: нужна сеть и пересборка `uv.lock`.
- **Судья ставит «хорошо» тому, чего нет.** Верните ему доказательство, которое не подтвердилось, и ужесточите
  пункт промпта; «отлично» без доказательства по каждому слову дескриптора совет засчитает как «хорошо».
- **Факт о данных устарел.** Исправьте раздел 5 скила `munnet-agents` — одно место на всех агентов.

## Чего не делать

- Просить судью или проверщика «заодно поправить»: прав на запись у них нет, а независимость понадобится потом.
- Принимать «отлично» без цитаты или команды.
- Показывать судьям оценки друг друга до того, как они оценили сами.
- Давать эксперту проверять собственную работу вместо проверщика.
- Звать полный совет на этапе 1: оценивать ещё нечего — нужны калибровка и «потенциал сюжета».

## Обслуживание

| Что | Где |
|---|---|
| Агенты | `.claude/agents/*.md` |
| Общий скил: правила, факты о данных, шкала жюри, правила анализа | `.claude/skills/munnet-agents/SKILL.md` |
| Хук «только чтение» для проверщиков, судей и совета и его тест | `.claude/hooks/readonly_guard.py`, `.claude/hooks/test_guard.py` |
| Превью лендинга для браузерной панели | `.claude/launch.json` |
| Проверка агентов и типограф Markdown | `.claude/tools/validate_agents.py`, `.claude/tools/typograph.py` |

После любой правки агентов, скила или хука — из корня репозитория:

```bash
PYTHONIOENCODING=utf-8 uv run --frozen python .claude/tools/typograph.py ".claude/agents/*.md" ".claude/skills/munnet-agents/SKILL.md" docs/agents.md
PYTHONIOENCODING=utf-8 uv run --frozen python .claude/tools/validate_agents.py   # «проблем нет»
PYTHONIOENCODING=utf-8 uv run --frozen python .claude/hooks/test_guard.py        # «failures: 0»
```

Валидатор сверяет фронтматтер, инструменты и скилы агентов, «когда не звать» в описании, дословные строки шкалы
у судей с разделом 6 скила, команду хука, пути в тексте, типографику и порядок этапов в скиле с `src/munnet/cli.py`.

- **Хук и агенты работают только вместе:** без файла хука проверщики не смогут запускать Bash (вызов
  блокируется) — это сразу видно на калибровке.
- **Версия Claude Code.** Локально стоит 2.1.156. Если поля `skills`, `hooks`, `effort` или список `Agent(…)`
  у председателя не поддерживаются, агенты всё равно работают: промпты велят прочитать скил файлом, а председатель
  переходит в режим «сводка».
- **Журнал самопроверки.** После каждого совета основная сессия дописывает в `docs/selfcheck.md` строку, которую
  выдаёт председатель (дата, режим, уровни, балл, топ-3 исправления); при следующем вызове передайте её
  председателю — он покажет динамику.
- **Документация.** При установке в `PLAN.md` исправлено авторство AVI и AVU (Biswas, Biswas, 2017), в `CLAUDE.md`
  добавлен блок «Агенты», по которому основная сессия выбирает агента. Ошибки в `docs/materials.md` (строки про
  `connection.parquet` и `market_access.parquet`, состав неполной панели, авторство AVI и AVU) исправляет владелец
  этого файла; пока правки нет, верен раздел 5 скила.
