# Корзина и регион: типы муниципальных образований по тратам жителей

Проект для [онлайн-конкурса СберИндекса 2026](https://sber.ru/sberindex/konkurs_sberindex), направление «Кластеризация».

**Вопрос.** Чем различаются муниципальные образования (МО), если смотреть, на что тратят деньги их жители, и сравнивать каждое МО со своим регионом?

**Главный вывод** ([отчёт, раздел 1](report/report.md)):

- Четыре типа лежат на одной оси — доле кафе и ресторанов в тратах жителей по сравнению со своим регионом: от
  сельских районов, где она ниже региональной, до крупных городов. Вместе с ней растут размер МО и уровень трат, то
  есть насколько жители тратят больше или меньше, чем в среднем по МО своего региона. Типы — ступени этой оси.
  В сети сходства корзин, по которой они прежде всего строились, типы разделены: в среднем 91% силы связей МО
  приходится на МО своего типа, а при случайном делении на группы тех же размеров было бы 25%. По уровню трат
  и экономике места чётких границ между типами нет: силуэт 0,007 по шкале от −1 до 1, где 0 значит, что МО одинаково
  близко к своему и соседнему типу.
- Ось видна и в розничном обороте Росстата: ранговая корреляция 0,55 (при 1 порядок совпадает полностью, при 0 связи
  нет). Сам уровень трат связан с розницей сильнее типов: 0,63; это сравнение мы добавили, уже зная итоги заранее
  записанных проверок. По составу типы близки к простому делению МО по уровню трат: совпадение разбиений — 0,31 по
  шкале AMI, где 0 — совпадение как у случайных разбиений, 1 — полное совпадение. Тип отдельного МО одинаков во всех
  вариантах расчёта у 578 из 1776 МО в сети (32,5%).
- **Практический совет аналитику региона и журналисту.** Изменения оборота и доходов небольшого или среднего МО
  (меньше 53,5 тыс. жителей, это четыре пятых МО) сверяйте со своим регионом. До десяти ближайших по расстоянию МО
  того же региона (дальше — соседи по региону) ближе к настоящему изменению, чем похожие по корзине МО других
  регионов, в 56,3% случаев. При равной точности было бы 50%. У самых крупных МО (53,5 тыс. жителей и больше) оба
  ориентира почти равны: свой регион ближе в 50,7% случаев. Смотрите на оба ориентира: какой из них лучше, данные не
  показывают.
- Не подтвердились три предположения. Первое: МО меняют тип за год чаще, чем дают случайные колебания. Их меряют
  сменами типа между нечётными и чётными месяцами одного года: обе половины описывают один и тот же год. При другом
  правиле связей между МО смен не больше, чем бывает на плацебо, то есть на наборах месяцев без хода времени.
  Надёжных смен типа (тип держится внутри каждого года и разный в двух годах) 148, а каждый двадцатый набор плацебо
  даёт больше 236. Второе: смена типа видна в обороте общепита Росстата. Третье: тип помогает подобрать сопоставимые
  МО. Проверки и тексты выводов на каждый исход мы записали до расчётов. Из шести проверок смысла типов две
  подтвердились частично, четыре — нет: три названы выше, четвёртая — что типы не повторяют простое деление по
  уровню трат (второй пункт).

**Откуда числа совета.** Проценты — среднее по трём показателям за 2023 → 2024: обороту общепита, отгрузке товаров
собственного производства (Росстат, без малого бизнеса) и доходам по налоговой отчётности 5-НДФЛ. Одни и те же
похожие МО входят в наборы многих МО. С учётом этого 95% интервалы (пределы, в которые доля попадает в 95 из 100
повторов расчёта на случайных наборах регионов) такие: 53,5–59,3% у небольших и средних МО, 45,5–55,9% у крупных.
Разница между крупными и остальными МО тоже неточная: её интервал — от −10,4 до +0,1 процентного пункта. Чем крупнее
МО, тем меньше выигрыш: от 58% у самых малых МО (до 11,7 тыс. жителей) до 55% у МО от 28 до 53,5 тыс. жителей.
Границу по размеру мы выбрали, уже видя первые результаты, и заранее её не записывали. Три четверти крупных МО
относятся к двум городским типам, поэтому влияние типа и размера по этим данным не разделить.


**Как сделано.** Мы связали МО в сеть по тому, насколько похоже тратят деньги их жители по сравнению со своим
регионом, разделили узлы сети на четыре типа и проверили смысл типов на показателях Росстата, которых не было
среди признаков. В сеть вошли 1776 узлов: МО с полным рядом трат за 24 месяца, а Москва и Петербург — по одному
узлу. Поэтому в сети 73 региона из 77, что есть в данных трат (2190 МО): в четырёх регионах полного ряда
нет ни у одного МО.

## Быстрый старт

Нужны Python 3.12 (допустимы 3.11–3.13), [uv](https://docs.astral.sh/uv/) и, только для этапа `data`, системная
библиотека libarchive: ею распаковывается RAR-архив справочника границ. В Ubuntu и Debian — `apt install libarchive13`,
в macOS — `brew install libarchive` и `export LIBARCHIVE=$(brew --prefix libarchive)/lib/libarchive.dylib`.
Команды запускаются из корня репозитория: относительные пути в конфиге считаются от него.

```bash
make setup   # окружение строго по uv.lock: uv sync --frozen
make all     # все этапы по порядку с параметрами из configs/default.yaml
```

Без `make` — те же команды через uv; цель `make <этап>` — это ровно
`uv run --frozen python -m munnet --config configs/default.yaml <этап>`:

```bash
uv sync --frozen
uv run --frozen python -m munnet all                      # все этапы, начиная с data
uv run --frozen python -m munnet panel eda features       # несколько этапов по порядку
uv run --frozen python -m munnet --help                   # список этапов и ключей
```

Для pip без uv есть [requirements.txt](requirements.txt), собранный из `uv.lock` (`make requirements`).

Код выхода: 0 — успех; 1 — нет входов этапа (не запущен предыдущий); 2 — этап не реализован; 3 — не сошлось
контрольное число или утверждение отчёта этапа перестало быть верным на данных (отчёт тогда не перезаписывается).

### Windows

`make` в Windows нет: запускайте команды `uv run …` из раздела выше в Git Bash. Команды ниже проверены в Git Bash
на Windows 10.

- Если в консоли кириллица превращается в «кракозябры», добавляйте перед командой `PYTHONIOENCODING=utf-8`:
  `PYTHONIOENCODING=utf-8 uv run --frozen python -m munnet panel eda`.
- Если `uv sync --frozen` не находит Python, передайте путь к нему явно:
  `uv sync --frozen --python <путь к python.exe версии 3.12>`.
- Системной libarchive в Windows обычно нет, и этап `data` падает на архиве `t_dict_municipal.rar`, когда тот уже
  скачан. Распакуйте его встроенным в Windows 10 и новее `tar.exe` (`tar` из Git Bash RAR не читает), запишите
  метку распаковки и повторите `data` — уже скачанные файлы он не скачивает заново:

  ```bash
  /c/Windows/System32/tar.exe -xf data/raw/borders/t_dict_municipal.rar -C data/raw/borders
  printf %s 319ed22684b77716641bc15b61f7325adc44e9fc47e9be2973d88412d27d21f5 > data/raw/borders/.extracted_sha256
  uv run --frozen python -m munnet data
  ```

  Метка — sha256 архива из `sources.borders.sha256` в конфиге, без перевода строки.

всё время — `cluster` и `interpret`. Время в таблице — однократные замеры, от прогона к прогону оно меняется:
прогон с нуля 03.10.2026 одной командой занял 3 ч 1 мин 35 с, из них `cluster` — 47 мин 23 с, `interpret` —
2 ч 2 мин. Тяжёлые шаги идут в 6 процессов (`clustering.impl.workers`), чтобы уложиться в 16 ГБ;

## Воспроизводимость

- **Окружение** — версии всех библиотек закреплены в [uv.lock](uv.lock); `--frozen` запрещает их менять.
- **Данные** — версии закреплены sha256 в `sources.*.sha256` конфига и сверяются при скачивании. Таблица
  версий — [отчёт, приложение В](report/report.md).
- **Случайность** — только от `seed: 42` в [configs/default.yaml](configs/default.yaml). Повторный прогон даёт
  те же метки и числа; меняются замеры времени и то, что из них выведено. Время записано в колонке
  `seconds` таблиц (`timing.csv` и других), в ключах `seconds` и `timing` файлов `facts.json`, в фактах
  `cl.time_*` этапа `cluster` и во времени изменения файлов (`qc.freshness` этапа `interpret`); от них
  меняются и отпечатки файлов (`inputs_sha256`, `facts_sha256`).
  Что сверено побайтно и на каких seed проверен выбор метода — отчёт, раздел 10 и приложение В.
- **Прогон с нуля 03.10.2026** в чистой копии (`git clone` коммита `5a2ea8b`, `uv sync --frozen`, Windows 10,
  от уже скачанных сырых данных; этап `data` не повторяли): код 0, 3 ч 2 мин; все таблицы, json, parquet
  и рисунки совпали побайтно с основным репозиторием, кроме замеров времени и производных от них отпечатков
  файлов. Linux, macOS и скачивание данных этим прогоном не проверены. Подробности —
  [docs/repro_2026-10-03.md](docs/repro_2026-10-03.md), скрипт сравнения — [scripts/compare_outputs.py](scripts/compare_outputs.py).
- **Числа в текстах** выводит код из файлов результатов: отчёты этапов в `docs/` собираются из шаблонов и руками
  не правятся, числа методологического отчёта прослежены до ключей в [report/numbers.md](report/numbers.md).
- **Предрегистрация.** Правила выбора, проверки и тексты выводов на каждый исход записаны в репозиторий
  до расчётов; журнал отступлений — [docs/interpretation.md](docs/interpretation.md)
  и [docs/landing_spec.md](docs/landing_spec.md), §4.

  Слепой прогон для отладки: `uv run --frozen python -m munnet interpret --blind <seed>` перемешивает типы
  по узлам и пишет в `outputs/interpret_blind/` с пометкой «СЛЕПОЙ ПРОГОН». Замороженные ключи блока `site`

- **Кэш `interpret`** — `outputs/interpret/cache/`. Ключ — хеш исходного кода модулей тяжёлых прогонов и тех

  процессов в ключ не входит. Правка текстов отчёта кэш не сбрасывает, правка расчётного модуля или этих
  параметров — сбрасывает (около 2 ч пересчёта). Чтобы посчитать с нуля, удалите папку кэша.
- **Повтор без следов в репозитории.** Скопируйте конфиг, укажите в копии свои `paths.interim`,
  `paths.processed`, `paths.outputs`, ключи `report` и `report_images` этапов и `site.build.out`, а `paths.raw`
  оставьте на скачанные данные; запуск — `uv run --frozen python -m munnet --config <копия> <этапы>`.

## Лендинг

Адрес — https://nik0mir.github.io/sberindex/, он заработает после публикации 08.10.2026. Открыть
лендинг локально:

```bash
uv run --frozen python -m munnet site                    # собрать страницу в site/ (site.build.out)
uv run --frozen python -m http.server 8000 -d site       # открыть http://localhost:8000
```

Этап `site` читает выходы `interpret` и завершается кодом 1, если их нет или они старше меток кластеризации.
Объёмная карта первого экрана работает только через локальный сервер: при открытии `site/index.html` как файла
(`file://`) вместо неё видна плоская запасная карта с текстом.

## Конфигурация

Все гиперпараметры, пороги и правила, записанные заранее, лежат в [configs/default.yaml](configs/default.yaml)
с комментариями. Ключи, добавленные после предрегистрации, помечены «НЕ ПРЕДРЕГИСТРАЦИЯ».
Свои параметры — в копии файла:

```bash
uv run --frozen python -m munnet --config configs/my.yaml cluster evaluate
make CONFIG=configs/my.yaml all
```


## Данные и лицензии

Исходные данные скачивает этап `data`; состав, покрытие и ловушки — [docs/materials.md](docs/materials.md),
версии — sha256 в конфиге. Часть сайтов Сбера не открывается со стандартным набором корневых сертификатов:
сертификаты УЦ для них перечислены в `download.ca_files` в [configs/default.yaml](configs/default.yaml), проверка
TLS не отключается.

- **СберИндекс** — безналичные потребительские расходы жителей МО по категориям трат, индекс доступности рынков,
  автодорожные и железнодорожные связи между МО:
  https://sberindex.ru/ru/research/data-sense-opisanie-nabora-dannikh-khakatona-sberindeksa-po-munitsipalnim-dannim;
  справочник границ и преобразований МО:
  https://sberindex.ru/ru/research/dataset-borders-and-changes-of-municipalities. Лицензия
  [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/deed.ru); производные данные проекта
  распространяются на тех же условиях. Данные скачаны 25.09.2026.
- **Росстат**, база данных показателей муниципальных образований в обработке «Если быть точным» — население,
  занятость и зарплаты по ОКВЭД2, оборот розницы и общепита, число организаций и ИП:
  https://tochno.st/datasets/bdmo, лицензия [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/deed.ru).
- **ФНС**, отчётность 5-НДФЛ по муниципалитетам в обработке «Если быть точным» — доходы и число получателей:
  https://tochno.st/datasets/ndfl; лицензия на странице набора не указана.
- **OpenStreetMap** — полигоны границ в справочнике СберИндекса; на картах — «© участники OpenStreetMap», лицензия
  [ODbL](https://www.openstreetmap.org/copyright).
- **Лендинг** использует three.js 0.170.0 (MIT) и шрифты Golos Text и Unbounded (SIL Open Font License 1.1); файлы
  и тексты лицензий лежат рядом со страницей в `site/vendor/`.
