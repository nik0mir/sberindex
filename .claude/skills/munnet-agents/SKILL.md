# Общие правила агентов munnet

Единственный источник фактов о данных и общих правил для агентов из `.claude/agents/`. Если факт здесь
расходится с `docs/materials.md`, верен этот файл: строки ниже перепроверены кодом 26.09.2026.
Поменялись данные или код — перепроверь запуском и сообщи, какую строку обновить. Кого звать на каком этапе —
`docs/agents.md`; после правки агентов или этого файла — `.claude/tools/validate_agents.py`.

## 1. Проект и агенты

Конкурс СберИндекса 2026, направление «Кластеризация». Подача — 08.10.2026, запасной день — 09.10.
Этапы и даты — `PLAN.md`, задача организаторов и схемы данных — `docs/materials.md`.

| Агент | Отвечает на вопрос | Правит файлы |
|---|---|---|
| `expert-data` | Правильно ли собраны данные и что в них видно? Панель, соединения, разведка | да |
| `expert-economist` | Какой экономический вопрос, что значат типы, кому это полезно? | да |
| `expert-network` | Какие правила рёбер и почему выбрано это? | да |
| `expert-clustering` | Какие методы, сколько кластеров, как меняются типы во времени? | да |
| `expert-icvi` | Как посчитаны SW, CH, S_Dbw, AVI, AVU, MQ и что они говорят? | да |
| `expert-viz` | Как показать результат: графики для жюри, лендинг, PDF | да |
| `expert-writer` | Как рассказать: отчёт, README, заявка | да |
| `judge-c1-methodology` … `judge-c6-viz` | Какой уровень по одной строке шкалы жюри? | нет |
| `judge-council` | Какой взвешенный балл и что делать первым? | нет |
| `check-facts` | Верны ли данные, соединения и каждое число в текстах? | нет |
| `check-repro` | Повторит ли посторонний расчёт с нуля? | нет |
| `check-ux` | Поймёт ли читатель без подготовки за 30 секунд? | нет |
| `devils-advocate` | Можно ли опровергнуть главный вывод? | нет |

Исполнитель исправления — всегда один из `expert-*` или «участник».

## 2. Окружение и команды

- Работай из корня репозитория. Windows: инструмент Bash — это Git Bash, `make` нет, цели `Makefile`
  вызывай напрямую. В облаке — Linux, команды те же.
- Python — только так (без переменной кириллица в выводе ломается):
  `PYTHONIOENCODING=utf-8 uv run --frozen python …`; короткий скрипт — через heredoc
  `PYTHONIOENCODING=utf-8 uv run --frozen python - <<'EOF'` … `EOF`.
- Этапы: `PYTHONIOENCODING=utf-8 uv run --frozen python -m munnet --config <yaml> <этап> …`;
  порядок: `data panel eda features network cluster evaluate dynamics site`; `all` — все, начиная с `data`.
  Этап 1 плана — `panel` (панель, справочник территорий, контекст Росстата и 5-НДФЛ) и `eda` (разведка
  и отчёт `docs/eda.md`); этап 2 начинается с `features`. Разделы разведки по отдельности — `eda --only e3`
  или `eda --only e3,e4`: пишут только свои рисунки, таблицы и итог в `outputs/eda/sections/`, а общие выходы
  (`facts.json`, `indicators.parquet`) и отчёт не трогают, поэтому разделы E1–E5 можно дорабатывать
  параллельно; сводку и отчёт пересобирает `eda --only syn` или полный `eda`. Код выхода: 0 — успех,
  1 — нет входов этапа (не запускался предыдущий, например `eda` без `panel`), 2 — этап ещё не реализован,
  3 — не прошла проверка (жёсткое контрольное число или заголовок графика, переставший быть верным).
- Выходы этапа 1 (ключ территории везде — `territory_id` int32): в `data/processed/` — `panel_long.parquet`
  (МО-месяц × 7 частей с кодами `all, food, marketplace, transport, health, cafe, other`), `panel_wide`,
  `territories` (2190 МО: регион, тип, точка, статус ряда), `territories_geo`, `context_long`, `context_annual`
  (МО × год, «на жителя», флаги качества), `okved_shares`; `outputs/panel/controls.json` (контрольные числа)
  и CSV покрытия с `unmatched.csv`; `outputs/eda/facts.json` (все числа отчёта), `figures/`, `tables/`,
  `indicators.parquet`; отчёт `docs/eda.md` с картинками в `docs/img/eda/` собирается командой и руками
  не правится (шаблон — `src/munnet/eda/templates/eda.md`).
- Тесты: `uv run --frozen pytest -q -p no:cacheprovider`. Линтер: `uv run --frozen ruff check .`
  и `uv run --frozen ruff format --check .`.
- Данные уже скачаны: `data/raw/hackathon/{consumption,market_access,connection}.parquet`;
  `data/raw/borders/t_dict_municipal_districts.xlsx` и `t_dict_municipal_districts_poly.gpkg`;
  `data/raw/bdmo/<код>.csv.gz`; `data/raw/ndfl/data_5ndfl_155_v20260722.parquet`.
- Библиотеки — только из `uv.lock`: numpy, pandas 3, pyarrow, scipy, `scikit-learn 1.9` (есть `HDBSCAN`),
  networkx, python-igraph, leidenalg, dtaidistance, geopandas, pyogrio, openpyxl, matplotlib, requests, pyyaml;
  dev — pytest, ruff. Нет: statsmodels, seaborn, plotly, libpysal, umap-learn, shap, aeon, pingouin, playwright —
  примеры из скилов с ними не запускай. Новая зависимость — только с обоснованием («чего не хватает»),
  открытой лицензией (п. 10.3 Положения) и согласием участника: пересобираются `uv.lock` и `requirements.txt`.

## 3. Стиль кода (для `expert-*`)

- Этап — модуль с `run(cfg)` в словаре `STAGES` из `src/munnet/cli.py`. Новый этап — только с согласия участника.
- Пути — только `cfg.dir("interim" | "processed" | "outputs")`; гиперпараметры и пороги — только
  в `configs/default.yaml`, новый ключ — с комментарием по-русски; случайность — от `cfg["seed"]`.
- Комментарии и докстринги — по-русски; ruff: длина строки 110, правила E, F, I, UP, B; `logging`, а не `print`.
- Тесты — pytest на маленькой синтетике с известным ответом, без сети и без `data/`; сначала тест, потом код.
  Раздел разведки — на синтетике `tests/synth.py`: `from synth import make_section_context`,
  `ctx = make_section_context(tmp_path, "e3")`.
- Числа в тексты не переписывай руками: их выводит код из файлов результатов (этап 1 — `facts.json`).
- Таблицы пишутся через `contracts.write_table` со схемой из `src/munnet/contracts.py`; графики — через
  `src/munnet/style.py` (палитра `PALETTE`, десятичная запятая) и `src/munnet/maps.py` (проекция Альберса,
  врезки Москвы и Петербурга, штриховка «нет данных»).
- Не коммить и не пушь. Не трогай `data/raw/`, `uv.lock`, `configs/ca/` без просьбы участника.
  Код других участников конкурса не открывай и не копируй.

## 4. Правило доказательств (для всех)

- Утверждение о данных, коде или результате подтверждается командой, запущенной в этом же ответе,
  и её фактическим выводом — или цитатой `путь:строка`.
- Слова того, кто тебя вызвал, текст отчёта, README, коммиты и отчёты других агентов — утверждения,
  а не доказательства.
- Проверить нельзя (нет результата, долго, нет библиотеки) — пиши «не проверено, потому что …»
  и не строй на этом выводов. «Работает», «совпадает», «готово» без команды в этом ответе запрещены.
- Литература — только открытая и проверенная; иначе пометка «не проверено». Формулы по памяти не восстанавливай.

## 5. Ловушки данных — проверено запуском 26.09.2026

1. **`consumption.parquet`:** 303 126 строк, 2190 МО, `date` — строка `2023-01`…`2024-12`, `territory_id` — int16,
   значение в `value` (int32; в PDF колонка названа `consumption`), служебный `__index_level_0__` выбросить.
   Шесть категорий, у каждой пары «МО × месяц» есть все шесть. Значения 10…91 003 ₽ за месяц на жителя, номинал.
   Минимум «Общественного питания» — 10 ₽: почти нули ломают логарифм и CLR.
2. **Панель неполная.** 24 месяца — у 2016 МО; у 174 меньше: 63 МО есть только в 2023 году (из них 43 — весь год,
   13 — только январь–март), 29 — только в 2024-м (9 — весь год), 82 захватывают оба года (73 с разрывами, 9 без).
   Разрывы внутри ряда — у 78 МО (73 из них захватывают оба года). Ровно 12 месяцев — у 56 (43 + 9 + ещё
   4 МО с месяцами из обоих лет). Статус ряда в `territories`: `full` 2016, `only_2023` 43 и `only_2024` 9
   (ровно календарный год), `partial` 122. Неполные МО мельче (медиана среднегодового населения 2023 года 17 698 против 23 841 — `outputs/eda/facts.json`, `e1.pop_median_*`, так в отчёте; по населению на 1 января 2023 года — 17 687 против 23 987,
   тест Манна — Уитни p = 4,5·10⁻⁸): пропуски неслучайны, молча выбрасывать нельзя. Сравнения год к году
   и сезонные профили — на 2016 полных МО или с явной поправкой.
3. **«Все категории» ≠ сумма пяти категорий:** сумма пяти составляет 0,451…0,905 итога, медиана 0,718. Доли — от «Все
   категории» плюс «Прочее» = итог − Σ5 (всегда больше нуля: медиана 28% трат по долям 2023 и 2024 годов вместе,
   27,1% — по долям 2024 года (`e4.share_median_other`), в Якутии и на Чукотке до 45–49%); складывать все шесть —
   двойной счёт. Доли — композиционные данные: CLR с мультипликативной заменой почти нулей (порог — в конфиге).
4. **Общий фон делает ряды похожими.** Медиана попарной корреляции логарифмов «Все категории» по 2016 МО — 0,914
   (10-й процентиль — 0,776); после снятия двусторонних эффектов «МО + месяц» — −0,014. Правила рёбер по рядам —
   только на остатках, лучше — на своём ритме по определению п. 5 (итог разведки — таблица T06 `edge_signal`
   в `docs/eda.md`). Простое вычитание средних точно лишь на сбалансированной панели: для всех 2190 МО —
   альтернирующие проекции (или оценка эффектов на 2016 полных МО).
5. **Свой годовой ритм слабый; определение одно на весь проект** (этап `eda`, раздел «Годовой ритм»,
   2016 полных МО): y = ln трат → снять линейный тренд МО по 24 месяцам → вычесть общий ритм календарного месяца
   (медиана по МО) → свой ритм; повторяемость r — корреляция своих профилей 2023 и 2024 годов, сравнение —
   с перестановочным нулём. Доля общего ритма — 0,731; медиана r — 0,178; надёжный свой ритм (r > 0,6 и размах
   больше 5%) — у 314 МО (15,6%, на нуле 1,4%), из них 29,3% севернее 60° при 9,6% среди МО с полным рядом
   (точка внутри полигона; 8,5% без 22 внутригородских территорий Петербурга). Пик в декабре — у 97% МО.
   Числа 0,40 и «30–40% МО» из ранних черновиков завышены трендом МО — не используй их.
   Сезонный признак без проверки надёжности — шум.
6. **Рубли номинальные.** Медианный рост 2024/2023 по 2016 МО — 1,151 (10-й процентиль — 1,098, 90-й — 1,192);
   медиана декабря выше ноябрьской на 19% в оба года. «Реальный рост» без дефлятора — ошибка: реальный —
   только с помесячным ИПЦ Росстата в `eda.cpi` со ссылкой; рост сравнивай с медианным ростом по МО, а не с нулём.
   Медианный месячный уровень МО — 13 881…70 561 ₽.
7. **Типы ключа разные:** `territory_id` — int16 в consumption, int32 в market_access, int64 в connection
   и в справочнике, строка в gpkg (без приведения соединение даёт 0 совпадений). Во всех выходах — int32.
8. **`market_access.parquet`:** 2571 МО, 110,3…1000 (по описанию набора нормирован от 0 до 1000); нет у 20 МО
   из consumption (22 в `docs/materials.md` — по всему списку МО).
9. **`connection.parquet`:** `highway` — 3 303 736 строк, каждая пара один раз (x → y); `railway` — 2 638 628 строк
   = 2 × 1 319 314, каждая пара в обе стороны: наивная симметризация всех строк удвоит железнодорожные рёбра.
   Без железнодорожной связи — 830 МО из consumption, без автодорожной — 18.
10. **Справочник границ:** срез на год `year_from <= Y < year_to` (у действующих версий `year_to = 9999`);
    в срезе 2023 года — 2188 из 2190 МО (нет преемников объединений 3014 и 3101), 2024 — 2187 (нет 1471, 1487,
    1847). ОКТМО записан как `79-701-000-000`: убрать дефисы, взять 8 знаков; код короче 8 цифр — ошибка,
    а не повод дописать ноль. Один код в разные годы бывает у разных МО (33 кода; 46759000 — у 1471 до 2024 года
    и у 3014 с 2024-го): соединяй только по срезу года. Объединения 2024 года: 1471 + 1487 → 3014
    (Павлово-Посадский), 1847 (и 1866 без трат) → 3101 (Сасовский); у предшественников траты за 2023-01…2023-12,
    у преемников — за 2024-03…2024-12; ряды не склеиваются. Карту года рисуй по МО среза: в `territories_geo`
    все 2660 МО справочника, и полигоны предшественников и преемника объединения перекрываются.
    Точка МО для карт, соседей и I Морана — `representative_point()` полигона: у 247 внутригородских
    территорий Москвы и Петербурга нет центра в справочнике, а при `shape` = 3 центр лежит в соседнем МО.
    Карты — в равновеликой проекции Альберса с `lon_0=100` (сшивает Чукотку у 180°).
11. **БД ПМО** (`data/raw/bdmo/*.csv.gz`):
    - Чтение: разделитель `;`, все колонки строкой (`pyarrow.csv` — секунды; иначе `01512000` → `1512000`);
      строки `mun_level` = «Муниципальное образование верхнего уровня»; `CD`, `ND`, `UD` — пропуск. Регион —
      только из справочника: `region_id` БД ПМО несовместим с `region_code` (01 — Алтайский край, 1 — Адыгея).
    - Порядок: фильтр разрезов → выбор периода → дедупликация → проверка. Дубли ключа — например, 144 пары
      «город + его внутригородской район» с одним ОКТМО: строка с `mun_type` = `mun_type_oktmo` приоритетнее.
    - Периоды: годовое значение — только «Январь-декабрь»; кварталы и «Январь-март»… — нарастающие итоги,
      одномесячные периоды («Январь», «Март») годовыми не бывают; зарплата «Январь-декабрь» уже среднемесячная
      (на 12 не делить). Организации и ИП — снимок «На 1 апреля» (запасные — июль, октябрь): «На 1 января 2024»
      есть только у 369 МО панели. Покрытие считай только годовым значением: по любому периоду оно завышено
      (зарплата 2024 года — 2129 МО против 2037).
    - Разрезы: занятость, зарплаты, оборот и отгрузка — без малого бизнеса; итог по ОКВЭД2 — строка «Всего
      по обследуемым видам экономической деятельности», буквы А, В, Е, Н в названиях разделов — кириллица.
      Часть разделов скрыта (сумма разделов — медиана 0,95 итога, раздел B пуст у 84% МО): «не раскрыто» =
      1 − сумма долей. Возрастные интервалы — через U+2012 (`0‒14`), берутся три группы трудоспособности.
      В Y48112027 строки «всё, городское, сельское» не складывать; доля горожан = городское / всё, у сельских
      МО городское пусто — 1 − сельское / всё, пусты оба (109 МО в 2023 году) — пропуск.
    - Население: ноль → пропуск (Краснинский район), у Кемеровской области в 2023 году нет «На 1 января»
      (запасной период с флагом), у Рязанской в 2024-м строк нет (перенос прошлого года с флагом). Пропуск
      в данных о гостиницах (Y47000004, Y48060002) — и «нет», и «скрыто»: нулём не заменять.
    - **Соединение по ОКТМО** — только по срезу справочника на год, в три шага: прямой код → код
      другой версии того же МО (население «На 1 января» записано под кодом прошлого года — Магадан) → мост
      `oktmo_stable` источника, запрещённый, если стабильный код достаётся двум МО среза (иначе Павловский
      Посад получит население вместе с Электрогорском). Прямой код важнее моста, значения частей после
      объединения не суммировать (Саратов). МО без значения — в `outputs/panel/unmatched.csv` с причиной.
12. **5-НДФЛ:** 34 млн строк — только `pyarrow.dataset` с фильтром до чтения. Доход — `Y777000006` со ставкой
    `tax_rate` = «Всего», получатели — `Y777000028` с `individual_type` и `income` = «Всего»; в обоих
    `tax_authority` = «Всего» (без фильтра — строки инспекций других регионов и 564 дубля ключа); значение ≤ 0
    или пустое удаляется до дедупликации. `Y777000030` на уровне МО почти всегда 0 (у 2212 из 2319 МО

## 7. Правила проверяющих (`judge-*`, `check-*`, `devils-advocate`)

- В репозитории ничего не создаёшь, не правишь и не удаляешь; git — только чтение (`status`, `log`, `diff`, `show`,

  если он сработал, не обходи его, а напиши, что хотел проверить.
- Этапы — только с временным конфигом (раздел 8); `data` и `all` не запускай.
- **Режимы** задаёт тот, кто вызвал: «этап N» — оцениваешь сделанное, несделанное помечаешь «не начато»
  (это риск, а не ошибка) и даёшь прогноз уровня при выполнении плана; «финал» — как жюри после подачи:
  чего нет в репозитории, того нет. Режим не указан — «финал», и скажи об этом в первой строке.
- Уровень — наивысший, все условия которого подтверждены доказательствами. Сомнение между двумя — нижний,

- Прирост от исправления Δ = вес × число уровней; порядок исправлений — по Δ × вероятность ÷ часы;

## 9. Первоисточники (проверено 26.09.2026, дополнено 28.09.2026)

- **AVI, AVU, ANUI** предложены в: Biswas A., Biswas B. Defining quality metrics for graph clustering evaluation //
  Expert Systems with Applications. 2017. Vol. 71. P. 1–17. Полный текст закрыт, поэтому формулы — по открытым
  пересказам (статус «по пересказу»): Shalileh S., Antonov E. A., Tsyplakova D. A. Cluster validity across attribute
  and network spaces: empirical benchmarks for attributed networks clustering // Doklady Mathematics. 2025. Vol. 112,
  no. 3. P. 553–564, формулы (18)–(22) на с. 555; VLDB 2023, https://www.vldb.org/pvldb/vol16/p3165-howie.pdf, формулы
  36–38; изолируемость и AVI — также arXiv:2212.10797 (Das и др., соавтор — A. Biswas), разд. 5.2, формулы (19)–(20):
  они совместимы с обоими вариантами счёта внутренних рёбер, упорядоченные пары следуют из Doklady (18) и VLDB (36).
  Реализация проекта — `src/munnet/icvi.py` (28.09 пересчитана независимым кодом, расхождение не больше 1e-15).
  Изолируемость кластера Iso_k = M_kk / vol_k: внутренние рёбра — **упорядоченные пары** (M_kk = 2 × вес внутренних
  рёбер; на двух треугольниках, соединённых ребром, 6/7 ≈ 0,857, а не 0,75), знаменатель — объём кластера; AVI —
  среднее по кластерам, больше — лучше. Объединяемость пары U_kl = M_kl / (out_k + out_l − M_kl), out — вес рёбер
  кластера наружу; AVU = (1/K) · Σ_{k≠l} U_kl, меньше — лучше; ANUI = AVI / (1 + AVI · AVU) (Doklady, формула 22;
  VLDB, формула 38), а не отношение AVI к AVU. Вариант с весами — суммы весов.
- Случайный базис AVI (проверено симуляцией 26.09.2026): на случайных метках с K равными кластерами
  изолируемость ≈ 1/K при счёте упорядоченных пар и ≈ 1/(2K − 1) при счёте неупорядоченных рёбер. Поэтому AVI
  разных K сравнивают только через случайный базис (z-оценка), а не в сырых значениях.
- **Свойства индексов на данных проекта** (28.09.2026, подтверждено тремя независимыми проверками): AVU ≡ 1
  при K = 2 и ≡ 2/3 при K = 3 на любом связном графе — на этих K она ничего не говорит (z не определена);
  на однородной SBM с равными кластерами AVU = (K − 1)/(2K − 3) у любых меток, истинных и случайных. У всех
  структурированных разбиений сети корзины при K ≥ 4 z AVU отрицательна: случайные метки — её «пол»,
  а цепочечная структура (градиент) даёт большую AVU и у истинного разбиения. z AVI и z MQ у графовых разбиений
  почти совпадают (τ Кендалла 0,94–1,00) и растут с K, хотя сырая MQ выходит на плато. S_Dbw на 10–11
  стандартизованных признаках вырождается: окрестности центров почти пусты, S_Dbw ≈ Scat или не определён.
  В табл. 3 Doklady AVI = 0,20 при K = 3 не согласуется с их же формулой (26) (≈ 0,67); в формуле (14) неравенство
  f записано наоборот (у Halkidi и др., 2002, формула 16, f = 1 при d ≤ stdev).
- MQ — модульность (Newman, Girvan, 2004): доля веса рёбер внутри кластеров минус её ожидание в нулевой модели
  с теми же степенями узлов, γ = 1; больше — лучше. Сырые значения сравнимы только на одной сети: между сетями
  разной плотности — через нулевую модель (перемешивание рёбер с сохранением степеней). Предел разрешения —
  Fortunato, Barthélemy, 2007.
- Называть Миркина и Шалилеха авторами AVI и AVU неверно (так было в `docs/materials.md` и `PLAN.md`).
  Шалилех, Антонов и Цыплакова эмпирически изучали поведение SW, CH, DBI, S_Dbw, AVI, AVU, ANUI
  на атрибутированных сетях (Doklady Mathematics, 2025, т. 112, № 3, с. 553–564): AVI убывает примерно как 1/K,
  AVU с ростом K падает к «полу», CH растёт с числом объектов (советуют CH/N), случайный уровень DBI и S_Dbw
  зависит от K.
- Методы для атрибутированных сетей — Шалилех и Миркин: SEFNAC — Complex Networks & Their Applications IX (Springer,
  2021, Studies in Computational Intelligence, т. 943, с. 3–14, DOI `10.1007/978-3-030-65347-7_1`); ICESi — PLoS ONE,
  2021, 16(7), e0254377 (не SEFNAC); Entropy, 2022, 24(5), 626 (KEFRiN); Journal of Classification, 2022
  (восстановление данных); Social Network Analysis and Mining, 2021.
- SW — Rousseeuw, 1987; CH — Caliński, Harabasz, 1974; S_Dbw — Halkidi, Vazirgiannis, ICDM 2001 (варианты
  реализаций расходятся — фиксировать свой, меньше — лучше); Leiden — Traag, Waltman, van Eck, 2019;
  устойчивость кластеров — Hennig, 2007; переходы — MONIC (Spiliopoulou и др., 2006) и Greene и др., 2010;
  хабы в kNN — Radovanović и др., 2010; остов — Serrano и др., 2009; вывод после кластеризации — Gao, Bien,
  Witten, 2022; композиционные данные — Aitchison, 1986.

## 12. Правила анализа — для всех, кто считает или проверяет числа

Лучшие практики разведки этапа 1 (они же проверяются в `docs/eda.md`); действуют и на следующих этапах.
Нарушение — находка для `check-facts` и судей.

1. **Робастность.** Центр — медиана, разброс — межквартильный размах и MAD × 1,4826; связи — ранговая корреляция
   Спирмена. Среднее — только рядом с медианой и с подписью, взвешено ли оно.
2. **Уровни — в логарифме** (траты 1-го и 99-го перцентиля различаются в 3,6 раза), подписи осей — в рублях.
   **Доли — композиция:** сравнение через CLR, сырые доли в корреляциях не используются.
3. **Два взвешивания рядом:** «типичное МО» — медиана по МО без весов, «типичный житель» — веса населения `pop_avg`
   (23 111 ₽ против 31 784 ₽ в 2023 году). В тексте ясно, о ком речь; «МО» и «житель» не путать.
4. **Номинал.** Рост подписан «номинал»; МО сравнивают по росту относительно медианы; «реальный» рост — только
   с ИПЦ из `eda.cpi` со ссылкой на источник.
5. **Регион или место.** Для показателя — η² региона и I Морана; корреляции — в целом и внутри регионов. Связь,
   которая держится внутри регионов, — свойство места, а не карта регионов.
6. **Сходимость и «догоняние»** — только в двух шкалах (п. п. и логарифмы); связь прироста с начальным уровнем —
   на раздельных месяцах (начало по нечётным, прирост по чётным), устойчивость — по полугодиям. Сходимость по CV
   не используется: он падает механически при общем росте.
7. **Пропуски — данные:** сначала проверить, случайны ли они (SMD, модель пропуска с AUC), потом решать;
   выводы — «о 77 регионах».
8. **Каждый выброс — с именем:** МО, регион, число и объяснение; непроверенная причина помечается «гипотеза».
9. **Корреляция — не причина:** «влияет», «зависит», «значимо» — только с методом и числом рядом; много
   сравнений — поправка Бенджамини — Хохберга или ранжирование без p-значений; размер эффекта — всегда.
10. **Воспроизводимость:** случайность — только от `cfg["seed"]`; каждое число текста выводит код из файлов
    результатов (этап 1 — `outputs/eda/facts.json`).
