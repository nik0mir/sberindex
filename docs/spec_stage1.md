## 0. Главное на одном экране

1. **Два новых этапа конвейера — `panel` и `eda` — перед `features`.** `panel` собирает панель, справочник
   территорий и годовой контекст Росстата и ФНС; `eda` строит графики, таблицы, `outputs/eda/facts.json`
   и отчёт `docs/eda.md`. Признаки узлов сети (attributes) — работа этапа 2 `features`, здесь их нет.
2. **Один ключ территории — `territory_id` типа int32** во всех выходах. ОКТМО — строка из 8 цифр и нужен только
   как мост к Росстату и ФНС.
3. **Седьмая категория «Прочее» = «Все категории» − сумма пяти.** Она всегда больше нуля (медиана 28% трат),
   поэтому доли шести частей — замкнутая композиция, и её можно анализировать через CLR.
4. **Соединение по ОКТМО — в три шага по срезу справочника на год:** прямой код → код другой версии того же МО →
   мост через `oktmo_stable` источника с запретом для объединений. Правило «опорный год Y − 1» из варианта
   инженера отвергнуто: оно отдаёт население объединённого округа предшественнику. Прямой код важнее моста,
   части не суммируются.
5. **Население:** «На 1 января», запасной период — «Значение показателя за год» (Кемеровская область, 32 МО);
   ноль → пропуск (Краснинский район); пропуск года → перенос прошлого года с флагом (Рязанская область, 26 МО).
6. **5-НДФЛ:** доход — `Y777000006` со ставкой «Всего», получатели — `Y777000028`, только `tax_authority` =
   «Всего». Показатель из `docs/materials.md` (`Y777000030`) почти везде равен нулю — конспект исправляем.
   НДФЛ и занятость Росстата считаются по месту работодателя: для 247 внутригородских территорий Москвы и
   Петербурга показатели «на жителя» по месту работы не считаются.
7. **Контрольные числа двух видов:** жёсткие — инварианты закреплённых sha256 входов (ошибка, код выхода 3),
   мягкие — покрытие контекста (предупреждение при отклонении больше 1%).
8. **Сезонность — одно определение:** снять линейный тренд МО → вычесть общий ритм календарного месяца →
   сравнить повторяемость своего профиля 2023 и 2024 годов с перестановочным нулём. Итог: устойчивый свой ритм —
   у 314 МО из 2016 (15,6%, на шуме 1,4%), в основном на Севере. Годовой цикл годится как слой, а не как главная
   ось; числа 0,40 и 30–40% из черновиков завышены трендом МО.
9. **Маркетплейсы — честная формулировка:** доля в п. п. растёт быстрее там, где тратят меньше (ρ = −0,72,
   внутри регионов −0,60), но догоняния по доле нет (ρ прироста с начальной долей +0,06), а в рублях богатые МО
   прибавляют больше (ρ +0,67). Сходимость по CV не используем.
10. **Отчёт — продукт для выбора сюжета за 15 минут:** «Главное за минуту» → матрица решения с весами из
    критериев жюри и автоматическими критериями отказа → разделы по вопросам. Заголовок графика — вывод с числом,
    числа только из `facts.json`, заголовок с проверкой роняет сборку, если вывод перестал быть верным.
11. **Восемь пакетов работ** без общих файлов: фундамент (F), панель (P), пять разделов разведки (E1–E5),
    сводка и отчёт (R). Новых зависимостей нет.

# Часть А. Панель и контекст

## А.1. Место в конвейере

```python
# src/munnet/cli.py
STAGES = {
    "data": ("munnet.data", "скачать и распаковать исходные данные"),
    "panel": ("munnet.panel", "собрать панель «МО × месяц × категория», справочник территорий и контекст"),
    "eda": ("munnet.eda", "разведочный анализ: графики, таблицы и отчёт docs/eda.md"),
    "features": ("munnet.features", "признаки узлов для сети (этап 2)"),
    "network": ...,  # без изменений
}
```

`Makefile`: `STAGES = data panel eda features network cluster evaluate dynamics site`. Запуск этапа 1:
`make panel eda` или (Windows без make) `uv run --frozen python -m munnet panel eda`.

Почему отдельные этапы, а не код внутри `features`:

- **Разные причины меняться.** `panel` меняется, только если меняются данные или правила соединения; `features` —
  модельные решения этапа 2, их будут перебирать много раз, и перечитывать ради этого 34 млн строк 5-НДФЛ незачем.
- **Разведка зависит от панели, а не от признаков.** Иначе круг: признаки выбираем по итогам разведки.
- **Жюри видит методологию по шагам** (критерий 1, 15%): одна команда — один шаг, строка в README на этап.

Коды выхода `cli.main`: 0 — успех, 2 — этап не реализован (`NotImplementedError`), 3 — не прошла проверка
(`QCError`: жёсткое контрольное число или заголовок графика, переставший быть верным). Сообщение называет,
что именно не сошлось.

Тест `test_unimplemented_stage_exits_with_code_2` переписывается сразу (пакет F) на подменённый модуль-заглушку
через `monkeypatch`: он больше не зависит от того, реализован ли `features`. `eda` не пересобирает панель:
если нет файлов `data/processed/`, он падает с сообщением «сначала запустите этап panel».

| `territory_id` | int32 во всех выходах; на входе int16 (траты), int32 (доступность рынков), int64 (справочник, связи), строка (gpkg) — приводить при чтении |
| ОКТМО | строка ровно из 8 цифр: `re.sub(r"\D", "", s)[:8]`; код короче 8 цифр — ошибка, а не дополнение нулями (так ловится потерянный ведущий ноль `01512000` → `1512000`); у справочника хвост после 8 знаков всегда `000`, иначе ошибка |
| Месяц | `date` — строка `ГГГГ-ММ` (как в источнике), `t` int8 — номер месяца 0…23 (2023-01 = 0), `year` int16, `month` int8 |
| Категории | коды `all, food, marketplace, transport, health, cafe, other` — единственный словарь, константа `contracts.CATEGORY_CODES`; подписи — `style.LABELS`; соответствие названиям источника — `panel.categories` в конфиге |
| Деньги | траты — int32, ₽ на жителя в месяц, номинал; производные — float64; единица — в имени колонки (`_krub` — тыс. ₽ в год, `_rub` — ₽ в год, `_pc` — ₽ в месяц на жителя) |
| Доли | float64 в [0; 1], не проценты |
| Parquet | pyarrow, snappy, `index=False`, отсортировано по ключу; схема проверяется `contracts.validate` перед записью |
| CSV для машин | UTF-8 без BOM, разделитель запятая, дробная точка; русская типографика — только в отчёте и на графиках |
| JSON | UTF-8, `ensure_ascii=False`, `sort_keys=True`, `indent=1`; без дат и путей машины |

Панель никого не выбрасывает. Порог «сколько месяцев нужно, чтобы МО стало узлом сети» применяют этапы 2–3;
разведка показывает, кого он отсекает.

## А.5. Справочник территорий: алгоритм (`panel.territory`)

1. `read_dictionary`: `pd.read_excel(dtype={"oktmo": str, "shape_linked_oktmo": str})`; `oktmo8 = normalize_oktmo`;
   `territory_id` → int32, `region_code` → int16.
2. `dictionary_slice(dic, year, last_year)`: `year_from ≤ Y′ < year_to`, где `Y′ = min(year, last_year)`
   (интервал полуоткрытый, 9999 — действует сейчас).
3. Версия для названий и типа — последняя из действующих в 2023 или 2024 году (у 1471, 1487, 1847 — версия
   2023 года, у 3014 и 3101 — 2024-го); `oktmo_2023`, `oktmo_2024` — из срезов.
4. `read_polygons`: gpkg через pyogrio, `territory_id` строкой → int32, проверка: все 2190 МО панели нашлись.
5. Проекция в `panel.crs`; `representative_point()` в проекции → `x_aea, y_aea`; обратно в WGS84 →
   `point_lat, point_lon`; `area_km2`. Упрощение — А.4. Центроид не использовать: у вогнутых МО он снаружи.
6. `lineage`: версии с `change_id_to` / `change_id_from` вида `union_*` среди МО панели → роли и `successor_id`.
   Переносы (`transfer_*`) и разделения не трогаем: `territory_id` тот же. Ряды не склеиваем.
7. `distance_to_capital`: центр субъекта — МО панели со статусом `capital` того же `region_code`; расстояние
   из `connection.parquet` (`type = highway`, пара записана один раз — искать в обе стороны; читать через
   `pyarrow.dataset` с фильтром по типу).
8. `market_access` — соединение по `territory_id`.

## А.6. Соединение по ОКТМО (`panel.crosswalk`)

Единый алгоритм для всех показателей БД ПМО и 5-НДФЛ. Проверен на реальных данных (`final_check/f01_join.py`).

```
Вход: rows — отобранные строки одного показателя (oktmo, oktmo_stable, year, dim, value, period_used, flag);
      dic — все версии справочника; pairs — пары (oktmo, oktmo_stable) источника; годы.
Пустые значения удаляются заранее. Для каждого года Y:
  S = dictionary_slice(dic, Y, last_year)            # ВСЕ МО среза, не только панель
  D = множество кодов oktmo8 среза S                 # «прямые» коды года
  R = rows года Y
  1. direct:  МО i получает строку R с oktmo = код i в S.
  2. version: для МО без значения — коды других версий того же territory_id (из всех версий справочника),
              если код не входит в D (не прямой код другого МО среза); первая по году версии, где есть строка.
  3. stable:  ST(i) = { pairs.oktmo_stable(c) : c — любой код i из всех версий };
              стабильный код, который достаётся двум и более МО среза S, запрещён (объединение: Л9);
              кандидаты — строки R с oktmo_stable ∈ ST(i) и oktmo ∉ D (строки чужих МО не «воруем»);
              одно различное значение → берём; несколько → строка с oktmo ∈ ST(i), иначе NA и флаг multi_row.
  Значение каждого МО несёт oktmo_used и method.
Прямой код всегда важнее моста; значения частей после объединений не суммируются (Л10).
```

- **Пары `(oktmo, oktmo_stable)`**: для БД ПМО — объединение пар из всех прочитанных файлов (3347 пар, конфликтов
  нет; код с двумя стабильными — исключить и записать в лог); для 5-НДФЛ — его собственные пары.
- **Магаданский сдвиг (Л4)** ловит шаг `version`; **преобразованные в 2024 году МО** (новый код, которого нет в
  справочнике) — шаг `stable`: в 5-НДФЛ 2024 года так находится 166 МО, в населении 2025 года — 108.
- **Пропуск и потери.** Каждое МО панели без значения показателя за год попадает в `outputs/panel/unmatched.csv`
  с причиной: `region_no_rows` (в регионе нет строк за год: Рязань 2024), `union_banned`, `multi_row`, `no_code`.

Результат на МО панели (значение не NA, проверено):

## А.7. Чтение БД ПМО (`panel.bdmo`)

Общие правила для всех файлов:

1. Чтение — все колонки строкой (ОКТМО `01512000` не теряет ноль), заголовок — первая строка gzip-файла:

   ```python
   with gzip.open(path, "rt", encoding="utf-8") as f:
       header = f.readline().strip().split(";")
   table = pyarrow.csv.read_csv(path, parse_options=pyarrow.csv.ParseOptions(delimiter=";"),
                                convert_options=pyarrow.csv.ConvertOptions(
                                    column_types={c: pa.string() for c in header}))
   ```

2. Только `mun_level` = «Муниципальное образование верхнего уровня»; годы `context.read_years`.
3. `CD`, `ND`, `UD` → NA во всех строковых полях (Л18); `value = pd.to_numeric(indicator_value)`; `year` → int16.
4. **Порядок обработки** (Л11): фильтр разрезов показателя → выбор периода по приоритету → дедупликация →
   проверка. Дедупликация: одинаковые значения схлопнуть; среди строк одного (oktmo, year, dim) приоритетнее
   строка с `mun_type == mun_type_oktmo` (город, а не его внутригородской район с тем же кодом); если значения
   всё равно разные — первая по приоритету, флаг `dup_conflict` (на населении — 1 случай).
5. **Периоды** (Л12, Л13): годовое значение — только «Январь-декабрь», запасной — «Значение показателя за год»
   там, где указано в конфиге. Кварталы и одномесячные периоды не используются никогда. Запасы — «На 1 января»,
   у организаций и ИП — «На 1 апреля» → «На 1 июля» → «На 1 октября».
6. **Разрезы → доли.** ОКВЭД2: `okved_section(label)` — итог = точная строка `context.okved_total` → `TOTAL`;
   «Раздел X …» → буква X, кириллица по `context.okved_letters` (Л16); прочие метки (подвиды торговли) — вне
   разрезов, отбрасываются. Возраст: `grup_2` = «Всего», три группы из `context.age.groups`; проверка: сумма трёх
   и «Всего» совпадают в пределах 1%, иначе флаг. Пол на этом этапе не нужен.
7. Комментарий «Аномальное значение показателя» (219 строк зарплат, в итогах «Январь-декабрь» 2023–2024 — 0) —
   флаг `anomaly`, значение сохраняется.

Показатели — таблица `context.indicators` в конфиге (часть Г). Инвестиции (`invest`) — только 2023 год,
низший приоритет: если не успевается, колонка остаётся NA, этап не падает.

```python
    & (ds.field("individual_type") == "Всего") & (ds.field("income") == "Всего")
```

- ОКТМО — колонка `object_oktmo` (строка), мост — собственный `oktmo_stable` файла.
- Значение ≤ 0 или пустое → удаляется до дедупликации (ноль дохода при ненулевых получателях — пропуск).
- Проверка на здравый смысл: доход на получателя — медиана ≈ 392 тыс. ₽ в год (2023) и ≈ 462 тыс. ₽ (2024).
- Зарплатная часть «По коду дохода 2000» на этом этапе не нужна (256 нулевых МО-лет) — отложено до этапа 2.

## А.9. Знаменатели «на жителя»

- Траты СберИндекса уже «на жителя»: на население их не делим; население для них — только вес в сводках.
- Годовые потоки Росстата и ФНС делим на среднегодовое население `pop_avg` и на 12 → ₽ в месяц на жителя.
- `pop_avg(2024)` требует 1 января 2025 года: оно есть у 1932 МО, у остальных 254 — `jan1_only`. Ошибка такой
  замены — половина годового изменения населения; флаг позволяет исключить эти МО в проверке устойчивости.
- Перенос (`carried`): только для населения на 1 января, только с предыдущего года и только для МО, которые есть
  в срезе справочника этого года (у 1471 и 1487 в 2024 году переноса нет — их больше не существует).
- Вес для сводок «типичный житель» — `pop_avg` того же года; «типичное МО» — без весов. Оба варианта всегда
  рядом, в тексте ясно, о ком речь.
- Произведение «траты × население» как «оборот МО» не публикуем: знаменатель СберИндекса (все жители или
  держатели карт) не раскрыт.

# Часть Б. Разведочный анализ

## Б.1. Принципы (обязательны для всех разделов)

1. **Робастность.** Центр — медиана, разброс — межквартильный размах и MAD × 1,4826; робастный
   z = (x − медиана) / (1,4826 · MAD); связи — ранговая корреляция Спирмена. Средние — только рядом с медианой
   и с подписью, взвешены ли они.
2. **Уровни — в логарифме.** Траты различаются в 3,6 раза между 1-м и 99-м перцентилем (в 5 раз между краями):
   распределения, карты и связи уровней — в логарифме, подписи осей — в рублях («20 тыс. ₽»).
3. **Доли — композиция.** Шесть частей (пять категорий и «Прочее») в сумме дают 1, нулей нет (минимум 10 ₽):
   сравнение — через CLR = ln(доля / геометрическое среднее долей), PCA — на CLR. Сырые доли в корреляциях
   не используются.
4. **Сезонность — одно определение** (раздел E3): снять линейный тренд МО → вычесть общий ритм календарного месяца →
   свой ритм; повторяемость 2023 ~ 2024 сравнивать с перестановочным нулём. STL и X-13 на двух циклах ненадёжны,
   statsmodels нет — и не нужен.
5. **Номинал и реал.** Рост 2024/2023 — номинальный, так и подписывается («номинал» в каждом заголовке про рост).
   Для сравнения МО используется относительный рост (МО к медиане страны), в нём общая инфляция сокращается.
   Реальный рост — только если в `eda.cpi` занесён официальный помесячный ИПЦ Росстата со ссылкой.
6. **Два взвешивания.** «Типичное МО» — без весов (медиана по МО), «типичный житель» — веса `pop_avg`. Разница
   большая: 23 111 ₽ против 31 784 ₽ в 2023 году.
7. **Пропуски — данные.** Сначала проверить, случайны ли они (SMD, модель пропуска с AUC), потом решать.
   Выводы формулируются «о 77 регионах», а не «о России».
8. **Каждый выброс — с именем.** В таблицах выбросов — название МО, регион, число и подсказка-объяснение
   (признаки контекста с |z| > 2, плюс ручное пояснение из `eda.annotations`). Непроверенная причина — «гипотеза».
9. **Регион или место.** Для каждого показателя — η² региона (доля межрегиональной дисперсии) и I Морана;
   корреляции — в целом и внутри регионов (ранги, центрированные по региону). Связь, которая держится внутри
   регионов, — свойство места, а не карты регионов.
10. **Сходимость и «догоняние»** — только в двух шкалах сразу (п. п. и логарифмы), связь прироста с начальным
    уровнем — на раздельных месяцах (начало по нечётным, прирост по чётным), устойчивость — по полугодиям:
    β-сходимость на лог-росте подвержена регрессии к среднему, CV падает механически при общем росте.
    Сходимость по CV не используется.
11. **Корреляция — не причина.** «Влияет», «зависит», «значимо» — только с методом и числом рядом.
12. **Воспроизводимость.** Все случайности — `np.random.default_rng([cfg["seed"], номер раздела])`; перестановки —
    `eda.permutations`; каждое число текста — в `facts.json`.

### E1. Что есть в данных (`s1_coverage.py`)

### E3. Годовой ритм (`s3_rhythm.py`)

**Модель** (только МО с `full`, 2016). Для МО i и месяца t = 0…23, y = ln `v_all` (для категорий — ln `v_<c>`):

1. Тренд МО: МНК `y_it = a_i + b_i·t` по 24 точкам; `d_it = y_it − a_i − b_i·t`.
2. Общий ритм: `g_t = медиана_i d_it` по календарному месяцу (свой для каждого из 24 месяцев).
3. Свой ритм: `o_it = d_it − g_t`; профиль года `o_i,Y,m`; повторяемость `r_i = corr(o_i,2023,·, o_i,2024,·)`.
4. Свой профиль `s_i,m` — среднее двух лет; размах `A_i = max_m s − min_m s` (лог-пункты, в тексте — %).
5. Надёжный свой ритм: `r_i > eda.season.reliable_r` и `A_i > eda.season.reliable_amplitude`.
6. Нуль: месяцы 2024 года переставлены внутри МО, `eda.season.null_repeats` повторов; доля надёжных на нуле.
7. Доля общего ритма: `1 − Σ o² / Σ d²` по всем МО.

## Б.5. Сюжеты, критерии отказа и матрица решения

Матрица — подсказка, выбор делает участник. Итоговый балл = Σ вес × балл (1–5). Веса выведены из критериев жюри:
сила сигнала 0,25 (интерпретация 30% требует обоснованных выводов); сеть и динамика 0,20 (сетевая структура
и сравнение методов — 30%); практическая ценность 0,20 (интерпретация); покрытие 0,15 (воспроизводимость и
обоснованность); объяснимость 0,10 (понятность методологии); риски данных 0,10. Веса — `eda.matrix_weights`.

Сюжет может стать **главным**, только если выполнены все его критерии отказа; иначе в матрице — «слой» или
«контекст» с перечнем невыполненных критериев, независимо от балла. Критерии считаются автоматически из фактов,
пороги — `eda.rejection`.

|---|---|---|---|---|

## В.2. Анатомия графика и правила

```
Заголовок-вывод (13 pt, полужирный, слева, ≤ 90 знаков)   «Где тратят меньше, доля маркетплейсов растёт быстрее: +5,5 против +2,6 п. п.»
Подзаголовок (10 pt, #595959, ≤ 120 знаков)               «Доля маркетплейсов в тратах, 2023 → 2024; квинтили МО по уровню трат 2023 года; n = 2016»
[поле графика: прямые подписи, акцент — один цвет, контекст — серый]
Подпись (8 pt, #595959)                                    «Источник: СберИндекс (CC BY-SA 4.0); расчёт munnet. Рисунок 12»
```

1. **Заголовок — утверждение с числом**, которое подтверждает сам график; не «Доля маркетплейсов по МО».
2. **Одна мысль — один график.** Две мысли — два графика или малые множители с общей шкалой.
3. **Подзаголовок — что показано:** показатель, единица, период, n, взвешивание, «шкала логарифмическая».
4. **Прямые подписи** вместо легенды до пяти серий; легенда — только у карт (шкала классов).
5. **Акцент** — один цвет на фокусной серии или точках, остальное — серый. Подписей МО — не больше 5–7.
6. **Шкалы честные:** столбцы от нуля; уровни — логарифм с делениями в рублях; доли — проценты; отклонения —
   ноль посередине. Нет двойных осей, круговых диаграмм, 3D, радуг, рамок и тяжёлой сетки.
7. **Сортировка** по значению, не по алфавиту; время — слева направо.
8. **Пропуски видны:** штриховка и пункт «нет данных СберИндекса», а не пустота, похожая на ноль.
9. **Каждый график** сохраняется с CSV своих данных, альт-текстом (≥ 40 знаков, описывает вывод, а не тип графика)
   и записью в `figures.json`.
10. **Источник** внизу: СберИндекс (CC BY-SA 4.0); для контекста — «Росстат, БД ПМО в обработке „Если быть
    точным“ (CC BY 4.0)» и «ФНС, 5-НДФЛ в обработке „Если быть точным“».
