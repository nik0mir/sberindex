# Типы локальных экономик России

Проект для [онлайн-конкурса СберИндекса 2026](https://sber.ru/sberindex/konkurs_sberindex), направление «Кластеризация».
Строим динамическую атрибутированную сеть муниципальных образований (МО): узлы — МО с экономическими
признаками, рёбра — экономическая близость, сеть пересчитывается по месяцам. Кластеры сети трактуем как типы
локальных экономик и прослеживаем, как они меняются во времени.

Статус: реализованы загрузка данных (`data`), панель «МО × месяц × категория» с годовым контекстом (`panel`),
разведочный анализ (`eda`, отчёт — [docs/eda.md](docs/eda.md)) и признаки узлов сети (`features`); остальные
этапы идут по [плану](PLAN.md).

## Быстрый старт

Нужны Python 3.12, [uv](https://docs.astral.sh/uv/) и системная библиотека libarchive
(для RAR-архива со справочником границ, нужна только этапу `data`): в Ubuntu/Debian — `apt install libarchive13`,
в macOS — `brew install libarchive` и `export LIBARCHIVE=$(brew --prefix libarchive)/lib/libarchive.dylib`.
В Windows без `make` этапы запускаются той же командой `uv run --frozen python -m munnet <этап>` из Git Bash
или PowerShell (раздел «Этап 1: панель и разведка»).

```bash
make setup   # окружение строго по uv.lock
make all     # все этапы с параметрами из configs/default.yaml
```

Без uv и make:

```bash
python3.12 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
pip install --no-deps -e .
python -m munnet all
```

Команды запускаются из корня репозитория: относительные пути в конфиге считаются от него.

## Этапы

| Этап | Команда | Что делает | Статус |
|---|---|---|---|
| data | `make data` | Скачивает данные СберИндекса, Росстата и ФНС (≈170 МБ, на диске ≈260 МБ), сверяет sha256, раскладывает по `data/raw/<источник>/` | готов |
| panel | `make panel` | Панель «МО × месяц × категория», справочник территорий, годовой контекст Росстата и ФНС, контрольные числа | этап 1 |
| eda | `make eda` | Разведочный анализ: графики, таблицы, `outputs/eda/facts.json`, отчёт [docs/eda.md](docs/eda.md) с матрицей выбора сюжета | этап 1 |
| features | `make features` | Узлы сети (Москва и Петербург — два узла-города), признаки узлов по окнам времени, ряды для рёбер | этап 2 |
| network | `make network` | Рёбра по семи правилам, разрежение, сравнение правил и выбор, динамическая сеть по скользящим окнам, отчёт [docs/network.md](docs/network.md) | этап 2 |
| cluster | `make cluster` | Кластеризация по признакам, по сети и на атрибутированной сети | план, этап 3 |
| evaluate | `make evaluate` | ICVI: SW, CH, S_Dbw, AVI, AVU, MQ | план, этап 4 |
| dynamics | `make dynamics` | Кластеры по скользящим окнам, переходы МО между типами | план, этап 3 |
| site | `make site` | Данные для интерактивного лендинга | план, этап 6 |

Список этапов и параметры командной строки: `python -m munnet --help`.

## Этап 1: панель и разведка

Из корня репозитория, после этапа `data` (данные уже в `data/raw/`):

```bash
uv run --frozen python -m munnet panel eda        # Windows без make: Git Bash или PowerShell
make panel eda                                    # то же через make
```

Один раздел разведки пересчитывается отдельно и пишет только свои файлы (рисунки, таблицы и итог раздела
`outputs/eda/sections/e3.json`), а общие выходы и `docs/eda.md` не трогает; сводка и отчёт собираются из
сохранённых итогов разделов:

```bash
uv run --frozen python -m munnet eda --only e3        # make eda ONLY=e3; несколько: --only e3,e4
uv run --frozen python -m munnet eda --only syn       # сводка, общие выходы и docs/eda.md
```

Разделы: `e1` — что есть в данных, `e2` — сколько тратят, `e3` — годовой ритм, `e4` — корзина и маркетплейсы,
`e5` — экономика места, `syn` — «регион или место» и матрица выбора сюжета. Коды выхода: 0 — успех; 1 — нет
входов (сначала `panel`); 2 — этап не реализован; 3 — не сошлось контрольное число или вывод в заголовке
графика перестал быть верным (тогда `docs/eda.md` не перезаписывается).

| Что появится | Где | В git |
|---|---|---|
| Панель, справочник территорий, годовой контекст (parquet) | `data/processed/` | нет |
| Контрольные числа и покрытие контекста | `outputs/panel/controls.json`, `outputs/panel/*.csv` | нет |
| Графики (PNG, SVG), данные каждого графика (CSV), таблицы (CSV) | `outputs/eda/figures/`, `outputs/eda/data/`, `outputs/eda/tables/` | нет |
| Все числа отчёта, реестры графиков и таблиц, показатели МО | `outputs/eda/facts.json`, `figures.json`, `tables.json`, `indicators.parquet` | нет |
| Отчёт разведки и его картинки | `docs/eda.md`, `docs/img/eda/` | да |

Разведка на реальных данных считается меньше минуты (замер 26.09.2026 на ноутбуке: весь этап `eda` — 42 секунды,
из них пять разделов — около 30, сводка с отчётом — около 10). Текст отчёта — шаблон
`src/munnet/eda/templates/eda.md`, числа в нём — только из `outputs/eda/facts.json`; править нужно шаблон,
а не `docs/eda.md`. Повторная сборка на тех же данных даёт побайтно тот же `docs/eda.md`.

Как читать отчёт: «Главное за минуту» — семь выводов со ссылками на рисунки; «Какой сюжет выбрать» — матрица
решения T14. В ней итог каждого сюжета разложен на часть «по фактам» (сила сигнала и покрытие) и экспертную
часть; критерии отказа посчитаны из фактов, а критерий, который меняет ответ при другой оценке той же величины
(граница интервала, другое определение «внутри регионов», выборка без Москвы и Петербурга), помечен
«на границе». Матрица посчитана и без 247 внутригородских территорий Москвы и Петербурга: от этого решения
зависит, какой сюжет проходит критерии. Под матрицей — быстрый прототип типов (T15, k-means): повторяют ли типы
сюжета регион, уровень трат, тип или размер МО; у каждого сюжета — внешняя проверка на показателях Росстата,
пример МО и кому сюжет полезен. Экспертные баллы можно поменять в `src/munnet/eda/stories.py` и пересобрать
отчёт командой `uv run --frozen python -m munnet eda --only syn`.

## Этап 2: узлы сети и признаки

После этапов `panel` и `eda` (или сразу после `panel`: `features` читает только `data/processed`):

```bash
uv run --frozen python -m munnet features             # Windows без make
uv run --frozen python -m munnet panel eda features   # этапы 1–2 целиком
make features                                          # то же через make
```

**Узлы.** 247 внутригородских территорий Москвы и Петербурга сворачиваются в два узла-города (`nodes.mode:
collapse` в `configs/default.yaml`): траты — средние районов с весами населения, население и потоки Росстата —
суммы, зарплата — с весами работников, получатели 5-НДФЛ Москвы — из строки «Субъект РФ» (сумма районов считает
людей дважды), у зарплаты и 5-НДФЛ Москвы — флаг выброса. «Относительно региона» — по группе региона: Москва
вместе с Московской областью, Петербург — с Ленинградской. У узла-города свой `territory_id` — 90000 + код
субъекта (90077, 90078); связь МО с узлами — `features_members`. Проверка чувствительности — `nodes.mode:
separate` (247 отдельных узлов) или `exclude` (без них). Тот же режим использует разведка: матрица сюжетов T14
и прототип T15 в `docs/eda.md` посчитаны на узлах.

**Узел сети** — узел с рядом не короче `features.min_months` месяцев (по умолчанию 24: 1776 из 1945 узлов);
остальные остаются в `features_nodes` с `is_node = false` и причиной.

| Что появится | Где | Ключ |
|---|---|---|
| Справочник узлов и связь МО с узлами | `data/processed/features_nodes.parquet`, `features_members.parquet` | `territory_id` |
| Корзина и уровень по окнам (год, полугодие, квартал): доли, CLR, CLR и уровень относительно группы региона, прирост доли маркетплейсов | `features_windows.parquet` | `territory_id`, `window` |
| Годовой ритм: летний избыток, декабрьский пик, свой ритм, его размах и надёжность | `features_rhythm.parquet` | `territory_id` |
| Экономика места по годам: занятость по ОКВЭД2, зарплата, горожане, возраст, население, доступность рынков, 5-НДФЛ | `features_place.parquet` | `territory_id`, `year` |
| Ряды для рёбер: помесячные CLR корзины, ряды ln трат без тренда и свой ритм по категориям | `features_basket_monthly.parquet`, `features_rhythm_monthly.parquet` | `territory_id`, `date` (и `category`) |
| Числа решения о сюжете на узлах, таблица признаков, типы | `outputs/features/checks.json`, `feature_table.csv`, `types_*.csv` | — |

Схемы — `src/munnet/contracts.py` (`FEATURE_SCHEMAS`, `NODE_SCHEMAS`). Этап на реальных данных идёт около
10 секунд; повторный прогон даёт побайтно те же файлы (случайность k-means — от `seed` конфига).

**Сеть** — после `panel features`, около 5 минут:

```bash
uv run --frozen python -m munnet network              # make network
```

Рёбра по семи правилам (косинус и расстояние корзин, корреляция, лаговая корреляция и DTW своего ритма, дороги,
гравитация) — `data/processed/network_*.parquet`; сравнение правил и выбор — `outputs/network/`; отчёт с формулами,
таблицей сравнения и выбором — [docs/network.md](docs/network.md). Основное правило — расстояние корзин
относительно группы региона, слой — корреляция своего ритма, контроль — дороги. Отчёт собирается, только если
все его утверждения верны на числах (иначе код выхода 3).

## Конфигурация

Все гиперпараметры лежат в [`configs/default.yaml`](configs/default.yaml): источники данных с контрольными
суммами, правила рёбер, методы кластеризации, набор ICVI, окна для динамики, `seed`. Чтобы поменять параметры,
скопируйте файл и передайте его явно:

```bash
python -m munnet --config configs/my.yaml cluster evaluate
make CONFIG=configs/my.yaml all
```

## Структура

```
configs/           гиперпараметры (YAML)
src/munnet/        пакет: один модуль или подпакет на этап, cli.py запускает их по порядку
tests/             тесты: make test
report/            методологический отчёт
site/              интерактивный лендинг
docs/materials.md  конспект условий конкурса и описание исходных данных
docs/eda.md        отчёт разведки данных (собирается этапом eda), картинки — docs/img/eda/
certs/             временно: сертификаты для сайтов Сбера, см. certs/README.md
data/, outputs/    создаются при запуске, в git не хранятся
```
